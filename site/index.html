Wiener Netze Smart Meter → Home Assistant

Reading an M1 smart meter (Iskraemeko) locally with a battery-powered ESP32 — no cloud, no gateway, no power outlet at the meter. Live consumption data lands in Home Assistant over your own Wi-Fi.

How it works

  • The meter does the pushing. M1 meters send a complete consumption telegram through their infrared customer interface roughly every second — no query, no wired bus, no installer access needed.
  • A passive IR head (a small photodiode module, 3.3 V) sits in front of the meter's IR window, about 5–10 cm away, and turns the light into a UART signal (9600 baud, 8N1).
  • A Wemos S2 Mini (ESP32-S2) runs a custom wiener_netze ESPHome component: it waits for the 105-byte frame, verifies the CRC-16/X-25, decrypts the payload with the meter's security key, and publishes the values to Home Assistant over the native ESPHome API.
  • Battery + deep sleep. There is no power outlet at the meter. The board wakes every few minutes, reads one telegram, sends it, and sleeps again. A voltage divider on the battery feeds the S2's ADC, so Home Assistant also shows the remaining battery.

The protocol, in one table

AspectValue
InterfaceInfrared customer interface (IEC 62056-21, mode E HDLC push)
Line rate9600 baud, 8N1
Frame105 bytes: 7E A0 header + system title + frame counter + 74-byte encrypted payload
IntegrityCRC-16/X-25 over the unencrypted header
EncryptionAES-128 (GCM-CTR stream) — key from the Wiener Netze smart meter portal, stored only on the device
ValuesActive/reactive energy (Wh, Wh, varh, varh) and active/reactive power (W, W, var, var) + meter timestamp
Privacy by design: the data path is meter → ESP32 → your network → Home Assistant. Nothing leaves the house, no cloud account, and the portal key (a credential) is written once into the device config — it is not shared anywhere.

What you get in Home Assistant

Energy

Import / export (kWh) and reactive import / export (kvarh) — usable for dashboards and cost tracking.

Power

Live active and reactive power, import and export (W, var).

Device health

Decoded-telegram counter, meter timestamp, Wi-Fi and battery status — you know when the read head needs attention.

Battery monitoring

Battery voltage on the S2's ADC via a 1 MΩ divider; state-of-charge estimate as a battery sensor.

Hardware & wiring

PartWiring
Passive IR read head (3.3 V, e.g. TSOP-type serial module or bare photodiode + amp)VCC → 3V3, GND → GND, DATA → GPIO21 (receive only; some heads need the signal inverted)
LiPo battery, 7000 mAh (3.7 V cell)to the board's 5V/VBUS pin, through the on-board regulator (a charged LiPo reaches 4.2 V and must not be applied to the 3V3 pin); the board has no battery charger — swap the pack when flat
Voltage divider (2 × 1 MΩ, optional 100 nF to GND)battery + → R1 → GPIO3 (ADC1) → R2 → GND; the ESPHome config maps the reading back to battery volts

The board is powered from the battery via the 5V/VBUS pin and the on-board regulator. In deep sleep the board itself draws only tens of µA — what matters overnight is the IR head's idle current (it stays on 3V3): a bare-phototransistor type costs a few µA, an amplifier module a few mA, so pick accordingly or switch the head's VCC.

Battery life

Per wake-up (boot + Wi-Fi ≈ 2 s, one telegram ≈ 1.5 s, publish ≈ 0.5 s) the board uses roughly 0.1–0.23 mAh. The meter pushes ~1×/second, so every wake-up always has a telegram ready — the wake interval is the only knob.

Building it yourself

Add the component from the GitHub repo to your ESPHome config (repo goes public after the bench test):

external_components:
  - source: github://zeha/wiener-netze-smartmeter@main
    components: [wiener_netze]

wiener_netze:
  uart_id: meter_uart
  security_key: "<32-hex key from the Wiener Netze portal>"
  read_timeout: 10s

Placeholders you must fill in: Wi-Fi credentials, the ESPHome API encryption key (openssl rand -base64 32), and the meter security key from the portal. The example config ships with deep-sleep wake-up every 5 minutes and the battery voltage sensor.
